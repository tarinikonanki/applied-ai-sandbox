## Feature: Add a character counter for each note.

## Plan from chat

Feature: Add a character counter under each note body.

Data-model changes:
No data-model change is needed. The app can calculate the character count directly from each note's existing `body` field when rendering the notes list. This avoids adding unnecessary fields to the note dictionary.

Route changes:
No new routes are needed. The existing home/list route should continue passing notes to the template. If the route currently prepares note data, it can either leave the notes unchanged and let the template calculate `note["body"]|length`, or add a temporary display value without changing the stored note structure.

UI changes:
Update the notes list template so each note shows a small line under the body, such as `Characters: 42`. The count should appear for every note, including notes with empty bodies.

Edge cases:
If a note body is empty, the counter should show `Characters: 0`. If the body has spaces or punctuation, those should count as characters. Existing notes should still render correctly, and existing tests should continue to pass.

Verification:
Run `pytest -q` to confirm existing tests still pass. Then run the app in the browser, create a note, and confirm the displayed character count matches the length of the note body.
